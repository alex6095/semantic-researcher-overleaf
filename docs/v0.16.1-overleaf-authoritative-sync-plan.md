# v0.16.1 Overleaf-authoritative Local Replica plan

## Purpose

Overleaf is the canonical project state. A selected local folder is a durable,
editable working copy used by VS Code, Zed, shells, compilers, and agents. A
local change is not canonical until Overleaf accepts it. The synchronizer must
retain local intent while it obtains current remote state, submits an operation,
and observes the accepted remote result.

This is the durable task checklist. Update phase status and the work log in the
same commit as every material implementation or design decision.

## Non-negotiable invariants

1. An acknowledged Overleaf document or project-tree revision is the only
   canonical state.
2. The local tree remains normally editable. An agent or shell never needs to
   coordinate with VS Code before saving.
3. A dirty local editor buffer is never overwritten by remote input. A clean
   editor model may refresh from synchronized local disk state.
4. Event timing, mtime, and log order are diagnostic hints, never proof for
   conflict ordering or deletion.
5. Uncertain states preserve both copies and enter a durable conflict; they
   never select a winner silently.
6. `.output/**` and extension metadata are internal. A project PDF, PNG, ZIP,
   CSV, and other files remain syncable by default.

## Operation model

| Kind | Canonical server operation | Required precondition | Conflict policy |
| --- | --- | --- | --- |
| UTF-8 document update | join current doc, rebase, apply OT, observe ack | document id and current version | 3-way merge; overlap conflicts |
| File/media update | guarded upload/replace file entity | entity id and remote digest/revision | preserve both blobs |
| File creation | upload then add file entity | expected parent/tree state | same-name remote entity conflicts |
| Folder creation | add folder entity | expected parent/tree state | incompatible existing entity conflicts |
| Rename/move | entity-id tree operation | entity id, parent, tree state | remote move/rename conflicts |
| Delete | entity-id delete/tombstone operation | entity id/revision and clean local baseline | local divergence retains file |

## Durable state model

The manifest records last accepted remote state. Add a durable
pending-operation journal instead of treating a watcher event as an immediate
imperative request.

Every journal entry needs:

- operation id, kind, affected paths, and entity id when known;
- accepted remote identity/revision/digest and parent identity;
- stable local snapshot digest and recoverable snapshot/staging reference;
- creation time only for diagnostics, never ordering;
- lifecycle: `queued`, `reconciling`, `submitted`, `accepted`, or
  `conflict`.

The first manifest-v3 slice covers regular file updates and deletes. Its
recoverable source is the selected local working-copy path; the journal binds
that source to a stable digest before remote I/O. It does not duplicate file
bytes into a staging area. Manifest v4 additionally records the verified
Overleaf document/file entity ID and stable local `dev:ino` identity for each
regular file. A missing or legacy identity cannot prove a move; tree
operations will add the required entity and parent identities before they can
share this journal.

Coalescing must retain the same user-visible outcome. A known rename must not
degrade into an unrelated delete plus create.

### Phase 1 - Local intent journal and status

- [x] Persist regular-file update/delete intent before remote I/O begins; clear
      it only after an acknowledged remote result or a verified equal state.
- [x] Coalesce repeated stable writes on the same path to the final local
      working-copy digest without relying on event timing.
- [x] Expose `Synced`, `Pending upload`, `Offline queued`,
      `Reconciling`, and `Needs attention` with counts.
- [x] Keep offline work non-blocking; known connection-unavailable failures are
      queued and logged rather than surfaced as a sync-failure notification.
      Never show a modal merely because the
      connection is unavailable.
- [x] On reload/Remote SSH reconnect, re-read the authoritative remote path and
      replay the regular-file intent through the existing guarded merge/delete
      path; a concurrent change remains a durable conflict.
- [ ] Extend the journal to file creation, folders, rename/move, and recursive
      delete only after their entity/tree preconditions are recorded.

### Phase 2 - Text documents

- [x] Use the official versioned `joinDoc` catch-up protocol when a subscribed
      cache needs refresh; validate every returned text operation or retry a full snapshot.

- [x] Convert official `otUpdateError` events into explicit failed writes;
      force full-snapshot verification and retain unresolved local intent.
- [x] Replay a source-identified in-flight OT once with official
      `dupIfSource` duplicate suppression; sender acknowledgement, explicit
      rejection, or missing identity stays fail-closed.
- [x] Replace direct VFS fuzzy patch rebasing with an explicit three-way merge;
      unmergeable overlap remains a conflict.
- [x] Before each submission, obtain a coherent subscribed `joinDoc`
      revision and rebase local text against it (the protocol fallback, which
      has no joinDoc subscription, retains its explicit response path).
- [x] Submit an OT update with current base version and wait for matching
      applied operation/revision before accepting it in the manifest.
- [x] Reconcile collaborator socket operations into clean local documents.
      A small bounded version gap is queued in exact revision order; a large
      gap immediately invalidates the cache and preserves the merge base.
- [x] Make malformed/gapped collaborator updates, bad acks, and unjoinable
      docs fail closed into snapshot retry/conflict rather than stale pushes.

### Phase 3 - Files and project tree

- [x] Record verified remote document/file and stable local `dev:ino` identity
      for regular files; incomplete or migrated identity never proves a move.
- [x] Journal a guarded regular-file move before its remote mutation; replay it
      only after revalidating source entity identity, destination absence, and
      the unchanged local inode/digest.
- [x] Complete cross-parent basename changes as the same entity's
      rename-then-move sequence; a proved halfway path resumes the second step
      rather than fabricating the requested destination in the local cache.
- [x] Correlate watcher-observed local renames only through an exact inode match;
      a short delay may collect a delete/create pair but is never ordering proof.
- [x] Verify the destination retains the original Overleaf entity after a move;
      any mismatch or occupied destination preserves both sides as a conflict.
- [ ] Model create, update, delete, rename, move, and mkdir as guarded entity
      operations.
- [x] For mkdir, persist the missing-path and parent-folder precondition before
      the request; persist the returned folder ID before final verification; a
      same-name folder after an unacknowledged request is a conflict.
- [x] Upload source PNG/PDF/ZIP/CSV by default; exclude only configured
      generated output paths, `.output`, and known TeX intermediates.
- [ ] Verify remote entity identity and postconditions after every mutation.
- [ ] Preserve a binary conflict as two recoverable copies; never byte-merge.
- [x] Block folder delete containing unresolved descendant operations.
- [ ] Block folder rename/move containing unresolved descendant operations.

#### Active tree-operation slices

- [x] Guarded durable mkdir with remote parent and created-folder identity.
- [ ] Bind recursive folder delete staging to folder/parent identity and prove
      its postcondition before clearing descendant state.
- [ ] Model folder rename/move as an ID-preserving durable operation; block it
      when a descendant operation is unresolved.
- [ ] Expose binary and tree conflict choices (Keep Local, Keep Overleaf, Keep
      Both) without discarding journal evidence.

### Phase 4 - Inbound reconciliation and conflict UX

- [ ] Subscribe before trusting HTTP text snapshots; replay remote events in
      revision order.
- [ ] Apply remote changes directly only to clean local paths.
- [ ] Add Base/Local/Overleaf 3-way text diff with Accept Overleaf, Accept
      Local, and Apply Merged Result.
- [ ] Add Keep Local, Keep Overleaf, and Keep Both for binary/tree conflicts.
- [ ] Preserve resolution artifacts until Overleaf acknowledges the choice.

### Phase 5 - Acceptance matrix and release

- [ ] Closed and open text edits from VS Code, Zed, shell, and agent.
- [ ] PNG/PDF/ZIP create, replace, delete, rename, and folder move.
- [ ] Web edits while local is clean, dirty, offline, and reconnecting.
- [ ] Long local writer, atomic-save editor, and local compiler output.
- [ ] Remote delete versus prompt local recreation; subtree conflicts.
- [ ] Reload/restart journal recovery and account/project isolation.
- [ ] Full test suite, lint, production audits, package integrity, and signed-in
      Remote SSH / web validation.
